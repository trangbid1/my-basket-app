# Agentic Workflow Documentation

## Overview

This document describes the standardized agentic workflow for the MyBasket application team. The workflow leverages the `@democratize-quality/mcp-server` to enable AI-powered API testing and validation.

## Purpose

The agentic workflow allows team members to:
- Automatically generate comprehensive API test plans from OpenAPI/Swagger schemas
- Execute API tests with intelligent test case generation
- Validate API behavior with minimal manual intervention
- Generate detailed test reports and documentation

## MCP Server Configuration

### Settings Location

The MCP server is configured in `.vscode/mcp.json` at the workspace root.

### Configuration with --agent Flag

To enable agentic mode for enhanced AI capabilities, update your `.vscode/mcp.json`:

```json
{
  "servers": {
    "democratize-quality": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "@democratize-quality/mcp-server@latest",
        "--agent"
      ],
      "cwd": "${workspaceFolder}",
      "env": {
        "OUTPUT_DIR": "./api-test-reports"
      }
    }
  },
  "inputs": []
}
```

### Configuration Parameters

| Parameter | Value | Description |
|-----------|-------|-------------|
| `type` | `stdio` | Standard input/output communication mode |
| `command` | `npx` | Node package executor |
| `args` | `@democratize-quality/mcp-server@latest`, `--agent` | Package name and agent flag |
| `cwd` | `${workspaceFolder}` | Current workspace folder |
| `env.OUTPUT_DIR` | `./api-test-reports` | Directory for test reports and plans |

### The --agent Flag

The `--agent` flag enables:
- **Enhanced AI Reasoning**: More sophisticated test case generation
- **Context-Aware Testing**: Better understanding of API relationships
- **Intelligent Test Planning**: Automated detection of edge cases and scenarios
- **Smart Error Handling**: Improved error detection and reporting

## Workflow Steps

### Step 1: Configure MCP Server

Ensure your `.vscode/mcp.json` includes the `--agent` flag as shown above.

### Step 2: Start Microservices

```bash
# Windows
npm run microservices:start:win

# Unix/Mac/Linux
npm run microservices:start:unix
```

### Step 3: Generate Test Plans

Use the `api_planner` tool to generate test plans for each service:

```javascript
// Example: Generate test plan for Product Service
api_planner({
  schemaUrl: "http://localhost:3001/api-docs/",
  schemaType: "auto",
  apiBaseUrl: "http://localhost:3001",
  outputPath: "./api-test-reports/product-service-test-plan.md",
  includeAuth: true,
  includeSecurity: true,
  includeErrorHandling: true,
  testCategories: ["functional", "edge-cases"]
})
```

### Step 4: Execute Tests

Use the `api_request` tool to execute generated test cases:

```javascript
api_request({
  method: "GET",
  url: "http://localhost:3001/api/products",
  sessionId: "product-service-tests"
})
```

### Step 5: Generate Reports

Use the `api_session_report` tool to create comprehensive test reports:

```javascript
api_session_report({
  sessionId: "product-service-tests",
  outputPath: "./api-test-reports/product-service-report.md"
})
```

## Best Practices

### For Team Members

1. **Always Use --agent Flag**: Ensure the MCP server is configured with `--agent` for optimal AI capabilities
2. **One Service at a Time**: Generate and execute tests for one microservice at a time
3. **Version Control**: Commit test plans and reports to the repository
4. **Regular Updates**: Re-generate test plans when API schemas change
5. **Review AI Output**: Always review generated test plans before execution

## Troubleshooting

### MCP Server Not Starting

1. Verify Node.js is installed: `node --version`
2. Clear npm cache: `npm cache clean --force`
3. Check network connectivity
4. Review VS Code output panel for errors

### Microservices Not Running

1. Check Docker is running: `docker ps`
2. Verify ports are available: `netstat -an | findstr "3001"`
3. Check service logs: `docker logs <container_name>`
4. Restart services: `npm run microservices:stop:win && npm run microservices:start:win`

### Test Plan Generation Fails

1. Verify microservice is running: `curl http://localhost:3001/api/health`
2. Check API docs are accessible: `curl http://localhost:3001/api-docs/`
3. Ensure OUTPUT_DIR exists: `mkdir api-test-reports`
4. Review MCP server logs in VS Code
